# School Manager для Codex

Реалізовано **93 команди MCP** для керування чинними можливостями програми українською з текстового або голосового чату. Codex розуміє запит, локальний MCP викликає відповідну функцію School Manager. Окремий ключ OpenAI для MCP не потрібний.

[Можливості, виключення та перевірки](../../docs/mcp-implementation.md) · [точний каталог усіх команд](../../docs/mcp-tools.json) · [початковий аудит](../../docs/mcp-capabilities-audit.md).

## Підключення на Windows

Спочатку встановіть School Manager **v2.14 або новіший** і запустіть програму.
На сторінці релізу завантажте окремий `SchoolManager-Codex-MCP.zip` та розпакуйте
його в постійну папку. Потрібні Python 3.12+ і команда `codex` у PATH.
Архів містить вихідні файли MCP, без Python-середовища й особистих даних.
У наявній папці проєкту можна використовувати `integrations/codex_mcp` без розпакування архіву.

З кореня проєкту:

~~~powershell
powershell -ExecutionPolicy Bypass -File integrations\codex_mcp\setup.ps1 -Register
~~~

Скрипт створює окреме Python-середовище, встановлює MCP SDK, реєструє school_manager у Codex і задає час очікування команди 360 секунд. Залежності основної програми не змінюються. Після встановлення або розширення набору команд перезапустіть Codex.

Команду також можна виконати з кореня розпакованої папки `SchoolManager-Codex-MCP`.
Залиште цю папку на місці після реєстрації: Codex запускає MCP саме з неї.

School Manager має працювати на цьому комп'ютері за адресою http://127.0.0.1:8001. Потрібна версія backend із routers/assistant.py, підключеним у backend/main.py — вона включена в реліз v2.14. Запуск із вихідного коду використовує ці зміни; встановлену програму потрібно оновити інсталятором. Попередній dist/mcp-preview не є актуальною збіркою цієї реалізації.

MCP не запускає другий backend або планувальник і не переносить базу між режимами запуску. get_status показує runtime=source або installed: використовуйте програму з потрібними робочими даними.

Для ручного підключення виберіть STDIO:

- Command: абсолютний шлях до integrations\codex_mcp\.venv\Scripts\python.exe.
- Arguments: абсолютний шлях до integrations\codex_mcp\server.py.
- Environment: PYTHONUTF8=1.
- startup_timeout_sec=20, tool_timeout_sec=360 у секції mcp_servers.school_manager.

Для вже зареєстрованого сервера тільки час очікування оновлюється так:

~~~powershell
integrations\codex_mcp\.venv\Scripts\python.exe integrations\codex_mcp\configure.py
~~~

## Приклади запитів

- «Створи нагадування на суботу об 11:00: годинне заняття з Максимом».
- «Створи теплий шаблон про перенесення уроку, з абзацами та емодзі».
- «У шаблоні про домашнє завдання зміни текст, залиш усі вкладення».
- «Заплануй цей шаблон у групу Frontend на суботу об 10:00 один раз».
- «Призупини автоповідомлення цієї групи».
- «Перевір, чи всі звіти за сьогодні були відправлені».
- «Покажи помилки звітів за останній тиждень».
- «Скороти промпт автозвітів; решту налаштувань залиш».
- «Перенеси заняття в розкладі звітів на неділю об 12:00».
- «Експортуй розклад у файл».

Ролі батьківського/учнівського чату не додаються: адресат визначається за наявними групами та точними ID. За неоднозначної назви потрібне уточнення. Автоповідомлення використовують чинні день тижня/щоденний режим і час. Конкретну календарну дату не можна мовчки підмінити днем тижня.

## Поведінка команд

check_reports, list_pending_reports і list_report_runs нічого не надсилають. send_message, send_template, send_report, resend_report та run_due_reports можуть реально надсилати повідомлення й виконуються лише за відповідним запитом. Тестовий режим звіту також передбачає Telegram-відправку. prepare_report_context звіряє контекст через штатний preview; це не генерація чернетки тексту.

Редагування передає лише запитані зміни. Шаблони зберігають невказані вкладення/наліпки, групи — Telegram ID та інші поля, промпт — інші налаштування й API-ключ. Чинні перевірки звітів, відвідування, повторної відправки та доставки залишаються у програмі.

UUID request_id підтримують створення задач/подій та повторне надсилання звіту. Повтор тієї самої дії використовує той самий UUID. Інші створення та ручні повідомлення не мають нового постійного захисту від повторів. Після тайм-ауту результат невідомий: автоматичних повторів немає. partial=true означає, що запис уже створено і треба завершити його редагуванням. Задачі/події редагуються з актуальною revision.

Для відносних дат використовується resolve_local_date, типовий пояс Europe/Kyiv; неоднозначний час переходу годинника вимагає уточнення. Системне нагадування потребує запущеної програми та ввімкнених сповіщень. Серія редагується як ціле; нагадування має конкретний момент.

Перевірка звітів читає локальний журнал і розклад за період до 31 дня включно, типово за останні 7 днів. all_sent=null не підтверджує успіху. Telegram-історія повторно не читається. Обмеження історичного розкладу й неповної вибірки зазначаються у результаті.

Сервер працює через STDIO, не відкриває мережевий порт і приймає адресу backend лише на loopback. Він не відкриває SQLite напряму, не запускає власні планувальники та не повертає ключі/паролі/токени у звичайних відповідях. Вхід у зовнішні акаунти завершується у програмі або браузері.

## Перевірки

~~~powershell
backend\venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
integrations\codex_mcp\.venv\Scripts\python.exe -m unittest discover -s integrations\codex_mcp\tests -v
integrations\codex_mcp\.venv\Scripts\python.exe integrations\codex_mcp\smoke_test.py --fixture
~~~

Режим --fixture запускає тимчасову базу без робочих планувальників і підміняє Telegram/AI. Він перевіряє справжній MCP handshake, HTTP-виклики, файли, шаблони, розсилки, промпт, курси, розклад, задачі, звіти та захист від повтору звіту. Реальні повідомлення не надсилаються, робочі дані не змінюються.

Без --fixture smoke-тест читає тільки get_status робочої програми. Актуальний каталог регенерується командою:

~~~powershell
integrations\codex_mcp\.venv\Scripts\python.exe integrations\codex_mcp\catalog.py
~~~
