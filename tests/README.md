# Перевірка доставки автозвітів

Локальні перевірки без надсилання:

```powershell
backend\venv\Scripts\python.exe -m unittest discover -s tests -v
```

`test_logika_report_sync.py` перевіряє звіряння завершеного заняття перед ШІ:
перестановку М2У5 → М2У4 на двох датах, відповідність коду й номера в курсі,
збереження даних до генерації, пошук за ID групи та датою, ручну генерацію,
недоступність Logika з наступною повторною спробою й невідомий код уроку.
Використовуються окрема SQLite-база та змодельовані відповіді Logika, Google
і Telegram; жодних реальних повідомлень ці тести не надсилають.

Реальні перевірки, що надсилають по п'ять позначених тестових повідомлень
лише у погоджені користувачем «тест 3» та «тест канал 4»:

```powershell
backend\venv\Scripts\python.exe tests\live_report_matrix.py --send-to-authorized-chats
```

Сценарії: звичайна доставка; втрачена відповідь після прийняття Telegram;
усі відповіді втрачені та історія тимчасово недоступна; одночасні ручні й
автоматичні виклики; помилка нагадування й оновлення курсу після доставки.

Після кожного сценарію виконуються десять додаткових перевірок, потім два
цикли реального планувальника з інтервалом 60 секунд і перевірка з нового
процесу. Історія Telegram має містити рівно одне повідомлення для кожного
маркера; журнал — `success`; номер наступного уроку — 9 замість 8; список очікування —
порожній. Звіт `result.json` та підтвердження нового процесу `restart-result.json`
зберігаються у `tmp/report-matrix-<ідентифікатор>/`.

Використовуються окрема тестова база і тимчасова копія Telegram-сесії.
Текст генератора AI та оновлення курсу підміняються контрольованими значеннями;
Telegram-доставка, перевірка історії та збереження стану виконуються реально.
Ці перевірки не встановлюють причину історичного тайм-ауту і не перевіряють
доступність Google AI або Logika. Старий встановлений `.exe` вони не оновлюють.
# Перевірка запуску

`python -m unittest discover -s tests -p 'test_*.py'` перевіряє також готовність
HTTP під час повільного Telegram/Logika, тайм-аути, скасування синхронізації
при закритті, збереження даних та оновлення заставки без очікування WebView2.

`python tests/startup_preview.py --desktop --delay 45` запускає нативне вікно
«ТЕСТ · School Manager» з окремою тимчасовою базою та штучною затримкою сервісів.
`--offline` імітує відсутність мережі, `--local-delay 10` дозволяє оглянути
заставку під час підготовки бази. Тест не використовує реальні акаунти чи розсилки.

Для перевірки стану меню між повними перезапусками додайте
`--data-dir tmp/menu-preview`: тестова `preview.db` залишиться в цій папці.
Згорніть меню, повністю закрийте тестове вікно та повторіть ту саму команду;
перевірте також розгорнутий стан. `test_interface_settings.py` перевіряє обидва
стани після повторного відкриття бази, валідацію та збереження інших налаштувань.
