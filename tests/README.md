# Перевірка доставки автозвітів

Локальні перевірки без надсилання:

```powershell
backend\venv\Scripts\python.exe -m unittest discover -s tests -v
```

`test_logika_report_sync.py` перевіряє звіряння завершеного заняття перед ШІ:
перестановку М2У5 → М2У4 на двох датах, відповідність коду й номера в курсі,
збереження даних до генерації, пошук за ID групи та датою, ручну генерацію,
недоступність Logika з наступною повторною спробою й невідомий код уроку.
Для індивідуальних занять і груп з одним учнем автозвіт дозволяється лише
зі статусом `PRESENT` у журналі конкретного заняття. Перевіряються відсутність,
`NO_LESSON`, неповні й суперечливі відмітки, повторна перевірка після виправлення
присутності, збереження відсутніх при загальній синхронізації та одночасна
синхронізація під час генерації звіту.
Використовуються окрема SQLite-база та змодельовані відповіді Logika, Google
і Telegram; жодних реальних повідомлень ці тести не надсилають.

Повторне надсилання доступне в «Журнал звітів» → «Відправити повторно».
Перевірки охоплюють початкову дату й тему, виправлену відвідуваність,
ручне уточнення відсутніх, подвійне натискання, тайм-аут і відновлення доставки.
Повторний звіт не змінює поточний розклад і не створює другого нагадування.
Для нових відправок зберігається знімок уроку; старі звіти Logika відновлюються
за датою. Старий локальний звіт без знімка й прив’язки до Logika не можна
безпечно відновити, тому застосунок показує пояснення.

`python tests/report_resend_preview.py` запускає інтерфейс для перевірки
на `http://127.0.0.1:8767/parents-report` з окремою тимчасовою базою.
Logika, ШІ й Telegram підмінені; перевірка не надсилає реальних повідомлень.

Реальні перевірки, що надсилають по п'ять позначених тестових повідомлень
лише у погоджені користувачем «тест 3» та «тест канал 4»:

```powershell
backend\venv\Scripts\python.exe tests\live_report_matrix.py --send-to-authorized-chats
```

Сценарії: звичайна доставка; втрачена відповідь після прийняття Telegram;
усі відповіді втрачені та історія тимчасово недоступна; одночасні ручні й
автоматичні виклики; помилка нагадування й оновлення курсу після доставки.

Після кожного сценарію виконуються десять додаткових перевірок, потім два
цикли реального планувальника з інтервалом 60 секунд і перевірка з нового
процесу. Історія Telegram має містити рівно одне повідомлення для кожного
маркера; журнал — `success`; номер наступного уроку — 9 замість 8; список очікування —
порожній. Звіт `result.json` та підтвердження нового процесу `restart-result.json`
зберігаються у `tmp/report-matrix-<ідентифікатор>/`.

Використовуються окрема тестова база і тимчасова копія Telegram-сесії.
Текст генератора AI та оновлення курсу підміняються контрольованими значеннями;
Telegram-доставка, перевірка історії та збереження стану виконуються реально.
Ці перевірки не встановлюють причину історичного тайм-ауту і не перевіряють
доступність Google AI або Logika. Старий встановлений `.exe` вони не оновлюють.
# Перевірка запуску

`test_report_schedule.py` перевіряє перенесення, редагування дати, паузу та відновлення,
збереження налаштувань і зупинку автозвіту при зміні розкладу під час генерації AI.
`python tests/report_resend_preview.py --schedule` відкриває тестовий сервер на
`http://127.0.0.1:8767` для перевірки меню правої кнопки та головної панелі.
База тимчасова, Telegram і AI підмінені; реальні повідомлення не відправляються.

`python -m unittest discover -s tests -p 'test_*.py'` перевіряє також готовність
HTTP під час повільного Telegram/Logika, тайм-аути, скасування синхронізації
при закритті, збереження даних та оновлення заставки без очікування WebView2.

`python tests/startup_preview.py --desktop --delay 45` запускає нативне вікно
«ТЕСТ · School Manager» з окремою тимчасовою базою та штучною затримкою сервісів.
`--offline` імітує відсутність мережі, `--local-delay 10` дозволяє оглянути
заставку під час підготовки бази. Тест не використовує реальні акаунти чи розсилки.

Для перевірки стану меню між повними перезапусками додайте
`--data-dir tmp/menu-preview`: тестова `preview.db` залишиться в цій папці.
Згорніть меню, повністю закрийте тестове вікно та повторіть ту саму команду;
перевірте також розгорнутий стан. `test_interface_settings.py` перевіряє обидва
стани після повторного відкриття бази, валідацію та збереження інших налаштувань.

`test_notification_activation.py` перевіряє адреси Windows-сповіщень, запуск
через системний протокол, передавання натискання в існуючу копію програми,
очікування готовності інтерфейсу та відкриття старого звіту з журналу.
Перевірка протоколу створює окремий тимчасовий запис реєстру й прибирає його;
реальні сповіщення й Telegram-повідомлення не надсилаються.

`python tests/notification_preview.py` запускає інтерфейс на
`http://127.0.0.1:8767` з підміненими акаунтами та тимчасовою базою.
Для імітації натискання задайте `window.__schoolManagerPendingNavigation`
і викличте подію `school-manager-navigate`. Перевірте ручний звіт
(`/parents-report?tab=pending&lesson_id=1`), журнал (`?tab=runs&run_id=1`),
автоповідомлення (`/auto-messages?message_id=1`), задачу
(`/tasks?item_id=a2111111111141118111111111111111`) та пропущені нагадування
(`/tasks?bucket=reminders`). Повторне натискання має відкрити той самий запис;
неіснуючий ID має показати коротке пояснення.

`node --test tests/test_api_client.mjs` перевіряє скасування запиту під час
читання відповіді, запізнілу відповідь, некоректний JSON та HTML замість API.
Такі відповіді не повинні підміняти список подій порожнім об’єктом.

`python tests/calendar_sync_preview.py` відкриває тестовий календар на
`http://127.0.0.1:8768/tasks`. Google замінено сховищем у пам’яті; база тимчасова.
Початковий стан імітує шість збоїв. Перевірте ручне відновлення, імпорт події,
створення/редагування/видалення серії в обраному календарі, приховування календарів
і швидкі повторні оновлення. `/api/preview/checks` показує лише тестові дані.

Віджети: `python tests/widgets_preview.py` запускає тимчасову базу на 8769.
Після запуску виконайте `python tests/desktop_widgets_check.py` через
`backend/venv`: перевіряються справжні вікна WebView2, три монітори, замочок,
прозорість, події з нагадуваннями, повторне відкриття та використання пам’яті.
Вікна тесту короткочасно з’являться на робочому столі. Робоча база,
налаштування користувача, Google та Telegram не змінюються.
