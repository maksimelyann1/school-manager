# Підключення Google Календаря до School Manager

Інтеграція потребує OAuth-клієнта **Desktop app**. Пароль Google вводиться лише на сторінці Google у звичайному браузері. Реальне підключення необхідно перевірити після створення клієнта.

## Стан налаштування проєкту School Manager — 29.09.2026

- Проєкт `school-manager-510108`: Google Calendar API увімкнено, OAuth-клієнт `School Manager Desktop` створено. Дозвіл `calendar.events` додано в Data Access і збережено; Google позначає його як неперевірений sensitive scope.
- Конфігурація `google-desktop-client.json` встановлена у корені репозиторію і `%LOCALAPPDATA%\SchoolManager`; файл виключено з Git. Читання конфігурації кодом перевірено.
- Audience: **External / In production**, підтверджено в Google Cloud.
- Сайт: https://maksimelyann1.github.io/school-manager/
- Політика: https://maksimelyann1.github.io/school-manager/privacy.html
- GitHub Pages публікує тільки сайт із гілки `gh-pages`; обидві сторінки повертають HTTP 200. Адреси та домен збережено в Branding.
- Право власності на сайт підтверджено в Google Search Console через HTML-метатег 29.09.2026. Верифікація бренду ще не завершена: Google вимагає зачекати 24 години після підтвердження власності перед повторною перевіркою. Після цього у Branding → View issues → I have fixed the issues слід повторити перевірку, опублікувати підтверджений бренд і перейти до перевірки sensitive scope у Verification Center.
- Публічний режим не означає завершеної верифікації: Google показує попередження про неперевірений застосунок. Новий sensitive scope `calendar.events` також потребує перевірки Google для широкого публічного використання.
- Реальний OAuth-вхід підтверджено користувачем у застосунку. Перевірено живий обмін із Google Calendar API: створення тестової задачі в застосунку → подія в керованому календарі; зміна події в Google → оновлення локальної задачі. Тестову подію й локальну задачу видалено. Це перевірка базового обміну, а не всіх крайніх випадків синхронізації.

## Одноразове налаштування розробником

1. Відкрийте [Google Cloud Console](https://console.cloud.google.com/) і створіть проєкт для School Manager.
2. У бібліотеці API увімкніть **Google Calendar API**.
3. У **Google Auth Platform** налаштуйте Branding і Audience. Для зовнішніх користувачів виберіть External. Поки застосунок у Testing, додайте свою адресу та адреси тестувальників до Test users.
4. У Data Access додайте дозволи:
   - `openid`, `email` — підпис підключеного акаунта;
   - `https://www.googleapis.com/auth/calendar.app.created` — створення окремого календаря застосунку й редагування його подій;
   - `https://www.googleapis.com/auth/calendar.calendarlist.readonly` — вибір календарів;
   - `https://www.googleapis.com/auth/calendar.events` — перегляд і редагування подій у календарях, де користувач має право власника або редактора.
5. У Clients створіть OAuth client із типом **Desktop app**, завантажте JSON. Web application або service account не підходять.
6. Назвіть файл `google-desktop-client.json` і покладіть у папку даних School Manager. Точний шлях видно у вкладці **Задачник → Google Календар**. Для запуску з вихідного коду це корінь репозиторію; встановлена Windows-версія використовує `%LOCALAPPDATA%\SchoolManager`.
7. Альтернатива для розробника: змінна середовища `SCHOOL_MANAGER_GOOGLE_CLIENT` із повним шляхом до JSON. Не додавайте файл до Git — назву вже внесено в `.gitignore`.
8. Натисніть «Перевірити налаштування», потім «Підключити Google». Після згоди повернення відбувається через тимчасовий порт `127.0.0.1`, без публічного сервера. Вікно входу діє 3 хвилини.

Для встановлення Python-залежностей: `backend\venv\Scripts\python.exe -m pip install -r backend/requirements.txt`. Токени зберігаються у Windows Credential Manager / macOS Keychain через keyring, окремо від SQLite. У JSON міститься конфігурація застосунку, а не токен користувача.

Для розповсюдження іншим користувачам розробник налаштовує один OAuth-проєкт. Кожен викладач входить у власний Google-акаунт; створювати окремий Cloud-проєкт кожному не потрібно. Перед публічним випуском перевірте вимоги Google щодо верифікації consent screen і дозволів. У режимі Testing refresh token для зовнішнього застосунку з Calendar scopes може мати короткий строк дії — повторний вхід у такому разі очікуваний.

## Як користуватися

1. Якщо Google був підключений раніше, натисніть **Оновити дозволи Google** і підтвердьте доступ до подій у браузері. Старий дозвіл лише на читання не дає права запису.
2. Натисніть **Завантажити календарі**. Календарі з правом власника або редактора доступні для створення й редагування; календарі з правом читання залишаються для перегляду. Позначте потрібні календарі.
3. У задачі чи події з датою ввімкніть **Google Календар** і виберіть календар. Без цієї позначки локальні задачі не експортуються. Задачі без дати залишаються локальними. Наявні події редагуються в їхньому поточному календарі; перенесення між календарями не підтримується.
4. Натисніть **Синхронізувати** для першої перевірки. Змініть назву або час у Google, повторіть синхронізацію та перевірте зміну в School Manager. Потім перевірте зворотний напрям.
5. Якщо запис змінено з обох боків, відкрийте панель Google та виберіть потрібну версію. До вибору обидві версії зберігаються.

«Виконано» є станом задачі School Manager; це не скасування події Google і не Google Tasks.

## Редактор подій

- Повторення: щодня, щотижня, щомісяця в заданий день тижня, щороку, у робочі дні або власний інтервал. Можна обмежити серію датою чи кількістю повторень. Локальні серії працюють без Google; для експорту ввімкніть синхронізацію.
- У календарі School Manager редагування й видалення повторюваної події застосовується до всієї серії. В інших календарях із правом запису редагується серія; окремі перенесення та скасування з Google відображаються, але винятки редагуються в Google.
- Гості додаються за email. Після збереження й успішної синхронізації Google надсилає запрошення; наступні зміни та видалення теж надсилаються гостям. Відповіді гостей завантажуються назад.
- Кнопка Google Meet створює конференцію після синхронізації, якщо календар Google підтримує Meet. Посилання з’являється в редакторі й деталях події. Помилки створення відображаються поруч із подією.
- Місцезнаходження й форматований опис синхронізуються в обидва боки. Панель біля слова «Опис» вставляє форматування в текст; воно відображається в деталях події та Google.
- Вкладення зберігаються локально в папці `planner_files` поруч із базою даних: до 10 файлів по 25 МБ. Вони не завантажуються в Google Drive і не входять у резервну копію лише `.db`; при перенесенні даних скопіюйте також цю папку.

Після оновлення перезапустіть застосунок для міграції бази. Для нового дозволу потрібен повторний вхід через кнопку «Оновити дозволи Google»; відкрита вкладка Google не замінює підключення акаунта в School Manager.

## Перевірка перед розповсюдженням

- Відмова у згоді, повторний вхід, відкликання доступу й завершення строку токена.
- Створення, зміна, видалення й відновлення події в обох напрямках.
- Конфлікт одночасної зміни, тимчасова втрата мережі й відновлення без дублів.
- Повторюваний урок, виняток із серії, цілоденна подія та перехід літнього часу.
- Від’єднання акаунта й підключення іншого: задачі старого акаунта не експортуються до нового.

Автоматичні тести використовують підставні відповіді Google. Вони не замінюють цей тест із налаштованим OAuth-клієнтом.
