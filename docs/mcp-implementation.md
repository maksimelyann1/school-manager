# Керування School Manager через Codex

Реалізовано **93 команди MCP**, які викликають чинні операції School Manager. Це керування наявною поведінкою програми. Пропозиції нових можливостей із початкового аудиту не підміняють цей обсяг.

## Доступні операції

| Стан | Стан запуску, зведення, версія, Telegram, сповіщення, кеш, стан інтеграцій та оновлення |

## П'ять виключень користувача

Не додавалися:

1. Нові ролі батьківського й учнівського чату.
2. Планування автоповідомлень на довільну календарну дату.
3. Чернетки звітів або окремий цикл генерації/погодження/надсилання тексту.
4. Серверна історія ручних розсилок та новий постійний захист їх повторної відправки.
5. Міст MCP до GUI-процесу для вікна/віджетів.

## Збереження чинної логіки

MCP працює через локальний HTTP API. Він не читає робочу базу напряму, не запускає другий планувальник і не відправляє звіти власною реалізацією. Команди відправки делегують чинним маршрутам програми.

Порівняння контрольних сум до й після розширення підтвердило незмінність `parents_report.py`, `auto_messages.py`, `report_delivery.py`, `models.py`, `database.py`, `services/planner/reminders.py`, `desktop_app.py`, `desktop_widgets.py`. Моделі, міграції та frontend не змінювалися. У backend додано окремий router асистента й його реєстрацію; новий маршрут читання курсу повертає теми без запису в базу.

Редагування шаблону зберігає невказані вкладення та наліпки. Повний PUT групи формується зі збереженням інших полів. Налаштування звітів передаються частково: зміна промпту не вмикає автозвіти й не замінює ключ. Не вказані `test` і `absents` не підміняються власними значеннями MCP.

Помилки й тайм-аути не запускають автоматичну повторну відправку. Існуючий захист задач/подій і повторних звітів використовує їхній `request_id`. Для ручних повідомлень новий постійний захист від дублювання не додається.

## Межі поточної програми

- Адресат визначається за фактичними групами. MCP не вгадує роль чату за однаковою назвою.
- У створеного автоповідомлення змінюються поля чинного update: текст, день, час, повтори. Нових команд заміни його чату/вкладень немає.
- Журнали повертають останні обмежені вибірки. Фільтри застосовуються до отриманих записів; повнота не заявляється. Для конкретного старого звіту доступний `run_id`.
- Перевірка звітів використовує локальні свідчення, без нової окремої звірки Telegram. Не додаються історія промптів або автоматичний зв'язок особистої події з рядком звітів.
- Локальна серія редагується як ціле; окремі винятки й нагадування на кожне входження не додаються.
- Імпорт застосовує чинний механізм без нового попереднього порівняння. Backup залишається штатною копією `.db`, без повного архіву файлів/віджетів чи нового узгодження WAL.
- OAuth, QR, коди, 2FA, ключі й паролі вводяться у програмі/браузері. Початок входу не означає успішної авторизації.
- Навігація використовує зареєстрований системний протокол. Керування вікном, віджетами та життєвим циклом закритої програми не додається.

## Перевірка

Успішно пройшли:

- **282 тести програми**, включно зі звітами, відвідуванням, планувальниками, перенесеннями, доставкою та захистом повторів.
- **39 тестів MCP**: параметри, часткове редагування, збереження файлів, тайм-аути, адресати, календар, секретні поля й налаштування Codex.
- **Наскрізний тест STDIO MCP → HTTP → тимчасова база**, який побачив усі 93 команди. Перевірено годинну подію, одне нагадування без дубля, відхилення застарілої revision, 5 станів звітів, шаблон із файлом/наліпкою, копіювання/отримання файлів, розсилку, автоповідомлення, промпт, курси, перенесення/паузу, XLSX, вкладення задачі та кошик/відновлення. Звіт пройшов штатну відправку з підміною зовнішніх сервісів; другу відправку відхилено чинним захистом.

У наскрізному тесті було по одному імітованому виклику ручної відправки, відправки звіту та AI. **Реальних Telegram-повідомлень — 0, робочий планувальник не запускався.** Робочі записи/промпт/налаштування не змінювалися. Живі Google, Telegram, Logika, голосовий сценарій та встановлена збірка з новими змінами цим тестом не підтверджені.

## Підключення й передача в збірку

[Встановлення MCP](../integrations/codex_mcp/README.md). На цьому ПК зареєстрований `school_manager`; оновлено лише його час очікування до 360 секунд. Для завантаження 93 команд потрібно перезапустити Codex. MCP SDK живе в окремому середовищі; основні залежності програми не змінені.

Іншому чату для збірки потрібні `backend/main.py` і `backend/routers/assistant.py` разом із чинними файлами програми. MCP запускається окремо з `integrations/codex_mcp`; його Python-середовище не потрібно включати в EXE. Інші користувачі оновлюють програму та підключають MCP на своєму ПК. Локальні `backups/`, `output/`, `tmp/`, робочі бази й середовища не є файлами реалізації для публікації.

Під час цього розширення EXE/інсталятор не збиралися; публікація й GitHub Actions не запускалися.
